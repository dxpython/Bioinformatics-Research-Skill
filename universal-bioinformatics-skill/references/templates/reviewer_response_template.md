# Response to reviewers template

> A structured framework for writing point-by-point responses to reviewers: format, reply strategy, phrasing templates, and example replies to common comments.

---

## 1. Response to reviewers format

### Standard structure

```
Response to Reviewers

Manuscript ID: [manuscript ID]
Title: [paper title]
Journal: [journal name]

Dear Editor and Reviewers,

We sincerely appreciate the valuable comments and constructive suggestions
from the editor and reviewers. We have carefully addressed all the comments
and revised our manuscript accordingly. The point-by-point responses are
provided below. All changes in the revised manuscript are highlighted in
[red / blue / tracked changes].

========================================
Response to Reviewer #1
========================================

Comment 1: [verbatim or summarized reviewer comment]

Response: [your reply]

[Revised text (Page X, Line Y-Z):
"Quoted revised wording" (optional, to show exact edits)]

---

Comment 2: [verbatim or summarized reviewer comment]

Response: [your reply]

---
... (continue for all comments)

========================================
Response to Reviewer #2
========================================

... (same format)

========================================
Response to Reviewer #3 (if applicable)
========================================

... (same format)


We hope that the revised manuscript now meets the standards of [Journal Name].
We look forward to hearing from you.

Sincerely,
[Corresponding author name]
On behalf of all co-authors
```

## 2. Revision description template

### Elements of each reply

```
1. Thanks (respect for the reviewer’s time)
2. Positive acknowledgment (show you understood the concern)
3. Concrete action (what you changed or added)
4. Location of changes (page/line or section; quoted text if helpful)
5. Further clarification (only if needed)
```

### Phrasing templates

#### Full agreement and revision

> We thank the reviewer for this insightful comment. We completely agree with this suggestion and have revised the manuscript accordingly. Specifically, we have [describe the change]. The revised text can be found on Page [X], Line [Y-Z] of the revised manuscript.

#### Partial agreement and revision

> We appreciate the reviewer's thoughtful comment. We agree that [the part of the concern you accept]. In response, we have [your change]. However, regarding [the other part of the comment], we respectfully note that [your explanation]. We have added a clarification in the Discussion section (Page [X], Line [Y-Z]).

#### Polite disagreement

> We sincerely appreciate this comment and understand the reviewer's concern. After careful consideration, we respectfully maintain our original approach/interpretation for the following reasons: [reason 1], [reason 2]. [Optional: supporting references]. Nevertheless, we have added a discussion of this point in the revised manuscript to acknowledge this alternative perspective (Page [X], Line [Y-Z]).

#### New analysis

> Following the reviewer's excellent suggestion, we have performed [analysis name]. The results showed that [brief result]. This new analysis has been incorporated into the revised manuscript as [Figure/Table X] (Page [X], Line [Y-Z]).

## 3. How to cite locations of changes

### Common methods

| Method | When to use | Note |
|--------|-------------|------|
| Page + line | Most journals | "Page 8, Lines 12-15" |
| Section + paragraph | Clear sectioning | "Section 3.2, paragraph 2" |
| Red/blue font | Emphasize edits | "Changes are highlighted in red in the revised manuscript" |
| Track Changes | When required | Submit Word with Track Changes |
| Clean + marked copy | Large revisions | Submit both clean and marked-up versions |

### Formats for quoting revisions

```
Option 1 (direct quote of revised text):
  Revised text (Page 8, Lines 12-15):
  "We performed CIBERSORT analysis to estimate the abundance of
   22 immune cell types in each sample (Newman et al., 2015)."

Option 2 (descriptive):
  We have added a new paragraph in the Discussion section (Page 12,
  Lines 5-18) to discuss the potential mechanism of [topic].

Option 3 (new figure):
  A new supplementary figure (Supplementary Figure S3) has been added
  to show [content]. The corresponding description has been added to the
  Results section (Page 9, Lines 22-28).
```

## 4. Describing new analyses

### Structure

```
1. Why the analysis was added (which comment it addresses)
2. Methods (brief: tools and steps)
3. Key results (one or two sentences)
4. Where it appears (section, figure, table)
5. Impact on the main conclusion (strengthened, unchanged, etc.)
```

### Template

> As suggested by the reviewer, we have performed [analysis name] to [purpose]. Specifically, we used [method/tool] to [steps]. The results demonstrated that [key result] (new Supplementary Figure S[X]). This additional analysis [supports/strengthens/does not change] our original conclusion that [original conclusion]. The corresponding methods, results, and figure legend have been added to the revised manuscript (Methods: Page [X], Lines [Y-Z]; Results: Page [X], Lines [Y-Z]; Supplementary Figure S[X]).

## 5. Careful wording

### Gratitude and respect

| Situation | Suggested phrasing |
|-----------|-------------------|
| Opening | "We sincerely appreciate the reviewer's constructive comments, which have significantly improved the quality of our manuscript." |
| Per comment | "We thank the reviewer for this valuable suggestion." |
| Acknowledge limits | "We acknowledge that this is an important limitation of our study." |
| Agree on importance | "We agree with the reviewer that this is a critical point." |
| Show understanding | "We understand the reviewer's concern regarding..." |

### Disagreement (polite)

| Situation | Suggested phrasing |
|-----------|-------------------|
| Polite pushback | "We respectfully note that..." / "With all due respect, we would like to clarify that..." |
| Evidence | "Based on the published literature [refs] and our analysis, we believe that..." |
| Alternative interpretation | "While we appreciate this alternative interpretation, our data more strongly support..." |
| Limitation but same conclusion | "Although we acknowledge this limitation, the overall pattern of our results consistently supports..." |
| Partial acceptance | "We agree with the reviewer on [Point A] and have made the corresponding revision. However, regarding [Point B], we would like to provide the following clarification..." |

### Describing results cautiously

| Avoid | Prefer |
|-------|--------|
| "This proves that..." | "This suggests / indicates / demonstrates that..." |
| "We discovered..." | "Our analysis revealed / identified..." |
| "The gene causes cancer" | "The gene may contribute to / is associated with tumorigenesis" |
| "The model perfectly predicts..." | "The model showed acceptable / good predictive performance..." |
| "These results definitively show..." | "These results provide evidence supporting..." |

## 6. Avoid over-promising

### Principles

1. **Do not promise experiments you cannot do** (e.g., animal or clinical work): state constraints and offer alternatives (public data, literature).
2. **Do not oversell revisions**: remaining limitations should be stated honestly.
3. **Do not commit to future work** unless you mean it: "future studies will be needed" is fine; avoid "we will perform" unless planned.
4. **Do not fabricate results**: report outcomes even if they differ from expectations.
5. **Do not dismiss the reviewer**: stay professional even if you disagree.

### Over-promise vs. reasonable reply

| Reviewer ask | Over-promise (avoid) | Reasonable reply |
|--------------|----------------------|------------------|
| Animal validation | "We will conduct animal experiments" | "We agree this would strengthen the study. Due to [reason], this is beyond the scope of the current bioinformatic study. We have acknowledged this as a limitation and noted it as an important direction for future experimental validation." |
| Larger sample | "We will collect more samples" | "We have now validated our findings using an additional independent dataset (GEO: GSE[XXXXX], n = [N]). We acknowledge that larger prospective cohorts would further strengthen these findings." |
| Clinical deployment | "The model can be used directly in clinic" | "While our model demonstrated promising predictive performance, we acknowledge that prospective clinical validation is essential before clinical implementation." |

## 7. Common comment categories and strategies

### Category 1: Statistical methods

#### Typical comment

> "The authors should justify the use of [statistical method]. Was the assumption of [normality / proportional hazards / independence] tested?"

#### Strategy

- Explain why the method was chosen.
- State whether assumptions were tested.
- If assumptions fail, describe alternatives or corrections.

#### Example reply

> We thank the reviewer for raising this important statistical concern. In the original analysis, we used [method] because [justification, e.g., it is widely used for this type of data and recommended by the tool developers]. In the revised manuscript, we have now verified the underlying assumptions:
>
> (1) **Normality assumption**: We performed the Shapiro-Wilk test on the expression data. For variables that did not follow a normal distribution (p < 0.05), we used the non-parametric Wilcoxon rank-sum test instead of the Student's t-test.
>
> (2) **Proportional hazards assumption**: We tested the proportional hazards assumption using Schoenfeld residuals (cox.zph function in R). All variables included in the final model satisfied this assumption (global test p = [value]). This information has been added to the Methods section (Page [X], Lines [Y-Z]).
>
> The revised results remain consistent with our original findings, confirming the robustness of our conclusions.

---

### Category 2: Sample size

#### Typical comment

> "The sample size is relatively small. How do the authors ensure the reliability of their findings?"

#### Strategy

- Acknowledge the limitation.
- Describe mitigations (external cohorts, bootstrap, etc.).
- Add validation data when possible.

#### Example reply

> We appreciate the reviewer's concern regarding the sample size. We acknowledge that the relatively limited sample size (n = [N] in the training cohort) is a limitation of our study. To mitigate this concern, we have taken the following steps:
>
> (1) **External validation**: We validated our model in [number] independent cohorts from different platforms (GSE[XXXXX], n = [N]; GSE[YYYYY], n = [N]). The consistent results across cohorts support the robustness of our findings.
>
> (2) **Bootstrap resampling**: We performed 1000 bootstrap resampling iterations to assess the stability of the selected features and the model performance. The average AUC across iterations was [value] (95% CI: [range]), indicating stable performance.
>
> (3) **LASSO regularization**: The LASSO regression approach inherently prevents overfitting, which is particularly important in small-sample settings.
>
> We have discussed this limitation in the revised manuscript (Page [X], Lines [Y-Z]) and emphasized the need for future validation in larger prospective cohorts.

---

### Category 3: Method choice

#### Typical comment

> "Why did the authors use [Method A] instead of [Method B]? [Method B] may be more appropriate for this type of data."

#### Strategy

- Justify Method A.
- If Method B is reasonable, run it and compare.
- If Method B is inappropriate, explain why.

#### Example reply

> We thank the reviewer for this constructive suggestion. We chose [Method A] for the following reasons: (1) [reason 1, e.g., it is specifically designed for RNA-seq count data]; (2) [reason 2, e.g., it has been widely adopted in similar studies and recommended by benchmark studies (refs)].
>
> Following the reviewer's suggestion, we have now also performed the analysis using [Method B] as a complementary approach. The results were largely consistent with those obtained from [Method A], with [X]% overlap in the identified DEGs (new Supplementary Figure S[X] and Supplementary Table S[X]). This concordance strengthens the reliability of our findings. We have added a brief note about this comparison in the Methods section (Page [X], Lines [Y-Z]).

---

### Category 4: Over-interpretation

#### Typical comment

> "The authors over-interpreted their bioinformatic findings. Correlation does not imply causation. The claims about mechanism should be toned down."

#### Strategy

- Acknowledge the point.
- Soften language ("prove" → "suggest"; "determine" → "associate").
- Flag where experimental validation is needed.

#### Example reply

> We sincerely thank the reviewer for this important reminder. We agree that our bioinformatic analysis can identify associations and generate hypotheses, but cannot establish causal relationships. We have carefully revised the manuscript to temper our language throughout:
>
> (1) In the Results section, we have replaced phrases such as "Gene X regulates pathway Y" with "Gene X expression was significantly correlated with pathway Y activity" (Page [X], Line [Y]).
>
> (2) In the Discussion section, we have added the qualifier "These computational findings suggest a potential role of [target] in [process], which warrants experimental validation" (Page [X], Lines [Y-Z]).
>
> (3) We have expanded the Limitations section to explicitly acknowledge that "the mechanistic inferences in this study are based on computational analysis and require experimental confirmation through functional studies such as gene knockdown/overexpression experiments" (Page [X], Lines [Y-Z]).
>
> We believe these revisions appropriately reflect the observational nature of our bioinformatic findings.

---

### Category 5: Data and code availability

#### Typical comment

> "The authors should make their code and processed data publicly available to ensure reproducibility."

#### Strategy

- Describe code sharing (e.g., GitHub).
- Cite public sources for raw data.
- Provide processed intermediates if appropriate.

#### Example reply

> We completely agree with the reviewer that reproducibility is of paramount importance. In the revised manuscript, we have taken the following steps to ensure full transparency and reproducibility:
>
> (1) **Code availability**: All analysis scripts (R and Python) have been deposited in a public GitHub repository (https://github.com/[username]/[repository]). The repository includes step-by-step instructions for reproducing all analyses and figures in this study.
>
> (2) **Data availability**: All datasets used in this study are publicly available. The TCGA data can be downloaded from the GDC Data Portal (https://portal.gdc.cancer.gov/), and the GEO datasets (GSE[XXXXX], GSE[YYYYY]) can be accessed from https://www.ncbi.nlm.nih.gov/geo/. Detailed download instructions are provided in the GitHub repository.
>
> (3) **Processed data**: The processed expression matrices, risk scores, and clinical data used for downstream analysis have been uploaded as Supplementary Data files.
>
> We have added a Data and Code Availability statement in the revised manuscript (Page [X]).

---

### Category 6: Lack of experimental validation

#### Typical comment

> "The findings are purely computational. The authors need to provide at least some experimental validation to support their key conclusions."

#### Strategy

- If wet lab is feasible, describe what was added.
- If not, use orthogonal public evidence (e.g., HPA, extra cohorts).
- State limits clearly in Discussion/Limitations.

#### Example reply

> We appreciate the reviewer's emphasis on experimental validation. In the revised manuscript, we have strengthened the evidence supporting our key findings through the following approaches:
>
> (1) **qRT-PCR validation**: We performed qRT-PCR on [N] paired tumor and adjacent normal tissue samples from our institution (with IRB approval, [approval number]) to validate the expression of [N] key genes ([Gene1], [Gene2], [Gene3]). The results confirmed that [Gene1] and [Gene2] were significantly upregulated in tumor tissues (p < [value] and p < [value], respectively), consistent with our bioinformatic predictions (new Figure [X]A-C).
>
> (2) **Protein-level validation**: We utilized immunohistochemistry data from the Human Protein Atlas (HPA, https://www.proteinatlas.org/) to examine the protein expression of our key genes. [Gene1] showed [strong/moderate] cytoplasmic staining in [cancer] tissues compared to [weak/negative] staining in normal tissues (new Supplementary Figure S[X]).
>
> (3) **Independent dataset validation**: We validated our risk model in [number] additional independent cohorts not used in model development.
>
> We acknowledge that comprehensive functional validation (e.g., gene knockdown, animal models) is beyond the scope of this bioinformatic study and have noted this as a future direction in the Discussion (Page [X], Lines [Y-Z]).

---

### Category 7: Figure quality

#### Typical comment

> "The figures need improvement. Please increase the font size, improve the color scheme, and add proper labels."

#### Strategy

- Respond positively and specifically.
- Align with the journal’s figure guidelines.

#### Example reply

> We thank the reviewer for the comments on figure quality. We have carefully revised all figures in the manuscript:
>
> (1) Font sizes have been increased to a minimum of [12] points to ensure readability.
> (2) The color scheme has been updated to a colorblind-friendly palette using the [viridis / RColorBrewer] package.
> (3) All axis labels, titles, and legends have been reviewed and standardized.
> (4) Figure resolution has been set to 300 DPI for all figures, meeting the journal's requirements.
> (5) P-value annotations have been added to all comparative plots.
>
> The revised figures can be found in the updated manuscript.
